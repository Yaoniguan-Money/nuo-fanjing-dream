# 《大傩幻梦》UI 重构适配规划

> 阶段：设计规划，尚未改动页面代码。
> 范围：桌面端优先，适配手机端；封面沿用现有完成版。

## 1. 目标与边界

本轮重构覆盖“问愿 → 面具匹配与戴面 → 幻梦对话 → 得面结果 → 图鉴与详情”五段体验。目标是让它们像同一部可进入的雾金丹青叙事：背景承担空间、雾与光；界面承担阅读、选择、确认和返回。

保留现有的路由、匹配逻辑、七幕剧情、图鉴收录、卡面资源和封面流程。UI 改动只替换视觉容器、排版、交互反馈和响应式布局，不改写剧情数据，也不把文字烘焙进图片。

## 2. 已确认的视觉方向

- 主方向：雾金丹青。云绢白、晴空青、松石绿、沙金、朱砂赭、木褐和墨青灰构成色阶；背景留白，主体精绘。
- 图鉴为独立深色子主题：保留现有深色收藏墙、雾金卡框与亮面卡面；只统一其字体、导航、按钮、状态和响应式规则。
- 信息层：墨青细线、雾金编号、浅纸签、极少量朱砂印。它用于指示状态与层级，避免抢占场景。
- 字体：进入打样筛选阶段。功能文字偏华文中宋式的有笔锋宋体，章节与角色名使用笔锋更重的楷体，长正文使用细宋体；最终选择与网页/应用嵌入授权一并确认。
- 草稿版 UI 的可继承部分：可拉伸的对话框结构、HTML 文字层、控件状态拆分、固定高度按钮、窄屏降级规则。
- 草稿版 UI 的不继承部分：红木高饱和底、整页金属/面具装饰、重发光主按钮、图片中烘焙的文字和把每个动作都做成厚重木牌的做法。

场景句：**游客在贵州晨雾与日光交界处进入傩坛；纸签般清晰的界面浮在留白里，动作克制，面具与山水才是画面中心。**

## 3. 信息架构与页面映射

| 流程段 | 现有实现 | 重构后的任务重点 | 桌面布局 | 窄屏降级 |
|---|---|---|---|---|
| 问愿 | `wish-input`、`get-face-ritual` | 输入、校验、继续与返回使用同一套控件 | 中央纸签输入区，场景留白占主画面 | 单列；输入框满宽；底部固定主操作 |
| 面具匹配/戴面 | `get-face-ritual` | 匹配状态、面具显影和入戏确认 | 面具居中，状态文案下置，返回在左上角 | 面具缩至安全高度；动效降级为淡入/定位 |
| 幻梦对话 | `dream-player` | 对话框、角色名牌、选项、章节 HUD、跳过/返回 | 场景全屏；对话框贴底；HUD 顶部两端 | 对话框改为底部抽屉式；HUD 收为一行 |
| 得面结果 | `get-face-result`、`dream-result` | 面具显影、职司、收录结果和下一步 | 面具与说明上下居中，主次操作分层 | 面具上移，操作区固定底部 |
| 图鉴/详情 | `codex-experience` | 卡牌墙、过滤/返回、详情阅读与关闭 | 4–5 列卡面，详情用全屏档案层 | 2 列卡面；详情纵向滚动；关闭固定右上 |

## 4. 组件系统

### 4.1 基础令牌

在 `src/app/globals.css` 建立单一令牌层，供所有 feature CSS 使用：

- 色彩：`--paper`、`--ink`、`--sky`、`--jade`、`--sand-gold`、`--vermilion`、`--wood`、`--line-subtle`。
- 字体：`--font-display`、`--font-ui`、`--font-mono`；正文最小 16 px，辅助说明最小 12 px。
- 间距：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 px 八级。
- 圆角：4 px（标签与输入）、8 px（纸签与容器）；卡面保持现有边框资产比例。
- 层级：场景 0、雾/遮罩 10、HUD 20、对话 30、浮层 60、模态 90。

### 4.2 复用组件

| 组件 | 用途 | 必须状态 |
|---|---|---|
| `RitualFrame` | 输入、对话、提示和确认容器；采用 CSS 九宫格或可拉伸 SVG 边框 | 默认、紧凑、阅读、错误 |
| `RitualButton` | 主操作、次操作、文字操作 | 默认、悬停、键盘焦点、按下、禁用、加载 |
| `RitualChoice` | 剧情选项与图鉴筛选 | 默认、悬停、已选、禁用、键盘焦点 |
| `RitualField` | 单行姓名与多行愿望输入 | 默认、聚焦、已输入、错误、禁用、字数提示 |
| `PageNav` | 返回首页、返回山门、关闭详情、跳过过场 | 桌面左上固定；手机安全区内固定 |
| `StageHud` | 章节、进度、可选跳过 | 默认、压缩、隐藏辅助信息 |
| `MaskReveal` | 匹配、戴面、得面三处面具动效 | 静止、显影、聚焦、完成、减少动态 |

组件只使用透明边框、少量角饰和 CSS 背景。带文字的 PNG 一律不进入生产 UI；草稿资产先重拆为无文字版，再决定是否使用。

## 5. 排版与层级规则

- 页面大标题只在“问愿、章节标题、得面、图鉴”出现一次；不在每个对话框重复使用超大字。
- 标题采用宋体，桌面 40–56 px；移动端 28–36 px。正文采用无衬线，桌面 16–18 px、行高 1.7–1.85。
- 标题区、正文区、操作区分别保留明确间距。面具或人物图不与长段文案争夺中心。
- 页面小标题用“章节编号 / 小功能名”两级，不使用多套分散的字距、颜色和样式。
- 当前散落的“返回首页”“返回山门”“退回山门”“重新观看”统一归为 `PageNav` 或次操作，保留对应业务行为。

## 6. 动效策略

动效用于解释状态变化，单次一般控制在 180–600 ms；剧情与戴面允许较长的场景性过渡，但用户可跳过。

| 场景 | 动效 | 约束 |
|---|---|---|
| 输入聚焦 | 边框由墨青转雾金，朱砂印点亮 | 180 ms；不做呼吸闪烁 |
| 提交匹配 | 输入区淡出，面具由雾中聚焦 | 不遮挡错误信息；网络等待显示可读文本 |
| 面具选中 | 非选中面具退为浅雾，目标面具抬升并出现柔光 | 保持原有选择逻辑；`prefers-reduced-motion` 只做淡入 |
| 剧情对话 | 新句淡入，角色名牌短暂显形 | 打字可跳过；不阻断点击继续 |
| 得面收录 | 卡牌短暂金线描边与朱砂落印 | 收录成功后提供前往图鉴和留在当前页 |
| 图鉴详情 | 卡面展开为黑雾档案层：左侧暖光扫过面具，右侧脸部沉入阴影，烟雾缓慢流动 | 手机改为自下而上平移；焦点进入关闭按钮 |

## 7. 响应式与无障碍要求

### 桌面优先

- 设计基准：1440 × 900；兼容 1280 × 720，保留最小可读区域。
- 剧情对话框最大宽度 960 px，文字行宽不超过约 64 个汉字；图鉴使用 CSS Grid，卡面列数按可用宽度伸缩。
- 场景图以 `object-fit: cover` 呈现，文案落在预设低信息区，避免依赖固定像素坐标。

### 手机适配

- 断点：960 px 以下进入紧凑布局；640 px 以下进入单列剧情布局。
- 触控目标至少 44 × 44 px；底部操作避开安全区；键盘出现时输入区不被遮挡。
- 对话框、详情、来源区允许纵向滚动；图片保持完整轮廓，禁止被裁掉关键面部。
- 只在 `hover: hover` 环境显示悬停强化；所有状态需有点击与键盘焦点等价反馈。

### 可访问性

- 每个图形按钮都具备文字或 `aria-label`；禁用状态保留文字可读性。按钮以分层的实感东方器物图片承载材质与光影，文字始终由 HTML 渲染，不烘焙进资产。
- 焦点环使用高对比雾金描边，不能只依赖颜色区分已选与错误。
- `prefers-reduced-motion` 关闭循环漂浮、雾粒和快速缩放。
- 对话框/图鉴详情打开后捕获焦点，关闭后返回触发卡面；ESC 关闭。

## 8. 分阶段实施顺序

1. **基础层**：建立令牌、字体加载、`RitualButton`/`RitualField`/`PageNav` 与全局响应式约束；不替换封面。
2. **问愿与匹配**：改造 `wish-input` 与 `get-face-ritual`，先验证输入、错误、等待、返回和面具显影状态。
3. **幻梦对话**：改造 `dream-player` 的 HUD、对话框、选项、跳过与返回；保持七幕数据与播放逻辑不变。
4. **得面与图鉴**：改造结果页、收录反馈、图鉴卡墙与详情层；复用同一导航与按钮词汇。
5. **资产清理与验收**：重新拆分草稿 UI 中带字资产，清除未使用的“空白/带字”双份图；核对桌面与手机关键状态。

## 9. 验收标准

- 从首页进入、问愿、匹配、完成七幕、得面、收录、打开图鉴详情，全程没有视觉风格跳变。
- 所有主/次按钮、输入框、选项和返回控件有统一形状、字号、状态与键盘焦点。
- 1440 × 900、1280 × 720、768 × 1024、390 × 844 四种视口完成关键路径，不出现遮挡、溢出或不可点击控件。
- 输入错误、网络失败、未收录图鉴、加载、禁用、已收录、详情关闭、减少动态模式都有明确界面状态。
- UI 文字由 DOM 渲染；所有生产资产带真实透明通道；页面无预览棋盘格、烘焙文字或拉伸变形边框。
- `npm run typecheck`、关键交互测试和浏览器视觉验收均通过。

## 10. 已确认约束与准备项

- 主流程采用“雾金丹青”明亮基调；图鉴保持深色收藏墙与亮面卡面，作为独立深色子主题。
- 草稿版的对话框、按钮与输入框需要重新拆分为无文字、可拉伸的边框层；当前 PNG 只作为尺寸与构图参考，不能直接接入。

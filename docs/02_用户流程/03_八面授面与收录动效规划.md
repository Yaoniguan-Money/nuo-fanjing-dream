# 八面授面、盖面入戏与得面收录｜交互规划

> 阶段：交互与美术规划，尚未进入页面实现。  
> 视觉责任：`purpleeerrr`；匹配规则接口：队友；前端接入可协作。  
> 适用链路：现实困惑 → 八面候坛 → 入戏 → 剧情结束 → 得面 → 傩谱。

## 1. 一条连续的授面仪式

三段不应被感知为三个独立特效。它们共用一条“金线确认”的视觉语法：

```text
困惑落入坛心
  ↓ 金线从文字收束到一面傩面
八面候坛，选中面具来到眼前
  ↓ 面具向镜头贴近，眼孔成为视野
进入对应剧情的第一幕
  ↓ 故事终局的金线重新召回此面
面具落坛，点击收录，飞入傩谱对应卡槽并点亮
```

固定视觉重点为：**面具 > 行动按钮 > 一句仪式文案 > 环境装饰**。雾金丹青保持深青阴影、橙金边缘光与大面积留白；粒子只承担方向提示，不持续飘动。

### 贯穿页面的 UI 外壳

剧情内容由独立卡片与队友维护，本任务只提供可迁移的表层组件：`RitualReturn`、`RitualInput`、`RitualPrimaryAction`、`DialoguePanel`、`StoryHud`、`BrandMark`。这些组件只读取标题、按钮文案、角色名和进度，不读取或改写剧情内容。

页面统一采用暗坛、烟雾、局部暖光与细金线；标题为宋体展示字，功能文字和正文依次降低字重。每屏只出现一个实感主操作，返回、重看、演示、剧情选择均为低权重控件。交互页移除右下大 Logo，封面和加载过场保留完整品牌标识。

### 本轮演示与合并策略

八面始终全部展示并允许成为匹配结果。当前仓库只注册四条故事，交互接口按八条故事设计；队友分支合并后，只需补齐 `maskId → storyId` 注册关系即可进入对应剧情。模型接入安排在交互完成之后，模型只返回已定义的 `maskId` 与 `storyId`。

### 统一数据契约

前端后续只认 `maskId`，不再用数组下标、显示名或四个写死的故事 ID 推断关系。

```ts
type RitualMask = {
  id: string;
  name: string;
  duty: string;
  storyId?: string;              // 有值才允许「入戏」
  codexSlotId: string;           // 得面飞入的唯一目标
  asset: { front: string; side?: string; back?: string; cover?: string };
  visualToken: { tint: string; emblem: string; pattern: string };
};

type MatchResult = { maskId: string; confidence: number; reason?: string };
```

匹配服务只返回 `maskId`。本地演示规则也输出同一字段。页面从 `maskId` 读取名称、职司、剧情、卡槽与素材，杜绝“开路将军剧情却收录九位土地神”的错配。

## 3. 八面匹配：候坛，不做纸片旋转

### 分镜与节奏

| 时间 | 画面 | 用户感受 |
| --- | --- | --- |
| 0–0.35 秒 | 困惑输入框淡入木纹，文字化为一条朱砂金线落到坛心 | 所问已被接住 |
| 0.35–1.4 秒 | 八面按先后从雾中显影，深处较小、较暗、略失焦 | 八职司正在候坛 |
| 1.4–2.8 秒 | 八面沿椭圆纵深轨迹缓慢换位一次；前景遮挡后景 | 空间成立，不像转盘 |
| 2.8–3.5 秒 | 其余七面退至雾中，目标面具沿金线走到中心 | 授面被确认 |
| 停留 | 显示“此面请你入戏”、角色名、职司与 `入戏` | 用户主动进入 |

### 空间原则

- 八面以“坛前半环”排布，角度固定为八个离散槽位。动画更新位置、景深、遮挡次序，不让一张 PNG 原地作 `rotateY`。
- 面具始终保持正面朝向镜头。前后关系由 `x / y / scale / blur / opacity / z-index` 计算，前景面具遮住后景的一小部分。
- 中心面具只有轻微呼吸和金线流动。停定后禁止持续抖动。
- 现有四个三视图可用于中心面具的边缘厚度与拖动视差；其余四面暂用正面透明底 + 景深候坛，页面不伪装为完整 3D 建模。
- 未来 GLB 模型进入后，替换 `MaskStage` 内部渲染即可，外部 `maskId`、时序和卡槽飞入逻辑保持不变。

### 文案层级

```text
小字：识 · 惑 · 请 · 面
主句：八面候坛
结果：开路将军
次句：职司 · 开障引路
按钮：入戏
```

名称和主句始终单行。窄屏按字号缩放与容器宽度处理，不能自动拆成多个孤立字。

## 4. 入戏盖脸：面具成为视野

点击 `入戏` 后，保留一个连续镜头，不切黑场也不出现纸片翻转。

| 时间 | 画面行为 |
| --- | --- |
| 0–0.18 秒 | 按钮与文字收束；中心面具停住，金线集中到鼻梁中轴 |
| 0.18–0.82 秒 | 面具沿镜头 Z 轴贴近，保留边缘厚度、木纹和侧光；大小覆盖至全屏 |
| 0.56–0.95 秒 | 眼孔区域显出第一幕环境的模糊光影，眼孔外仍是面具木纹 |
| 0.95–1.15 秒 | 木纹与雾完全退场，第一幕环境清晰；对白框随后进入 |

### 素材接口

八面都需要一组：

1. `front.png`：正面透明底，眼孔真实透明；
2. `side.png`：侧面或边缘厚度参考，用于中心面具的轻微鼠标视差；
3. `back.png`：同一面具的真实背部结构、凹面、系绳与木纹；
4. `cover.png`：适合 16:9 近距离覆盖的面具正面，可直接复用主面具并由 CSS 放大；
5. `eye-window.svg`：与眼孔位置一致的透明遮罩；
6. `story-entry.webp`：该剧第一幕的无文字环境图，由剧情分支提供，交互层只消费路径。

`eye-window.svg` 的透明区域只用于露出剧情环境，不能以黑色矩形代替。素材验收先在浅灰、白、深青三种底色上检查眼孔、轮廓与半透明边缘。

### 实现接口

`MaskStage` 提供 `mode="orbit" | "selected" | "flip-to-back" | "cover" | "reveal"`。选中面具先展示正面，沿垂直轴翻至侧厚，再以背面朝向玩家完成盖脸。当前阶段使用正、侧、背透明图与 GSAP 空间位移实现；模型到位后将内部替换为 WebGL/Three.js 画布，画布透明，页面底图继续由现有 UI 承担。

## 5. 得面收录：从剧情终局飞入傩谱

### 分镜与节奏

| 时间 | 画面 | 交互 |
| --- | --- | --- |
| 剧情结束后 0–1.1 秒 | 剧情终局降暗，角色对应面具从上方落到坛心；金线点亮轮廓 | 无操作，保证落坛完成 |
| 停留 | 小字“幻梦已尽 · 得面已成”，角色名、职司与一句回响 | `收录此面` 可点击 |
| 点击后 0–0.25 秒 | 固定面具与按键，傩谱界面在后方显影，目标卡槽处于未点亮状态 | 防止重复点击 |
| 0.25–0.95 秒 | 面具沿弧线从画面中心飞入目标卡槽，先缩小再落入；金线留下一次轨迹 | 目标卡槽接住面具 |
| 0.95–1.35 秒 | 卡面描金、翻正并点亮；其他卡保持静止 | 自动聚焦新收录卡 |

### 关键规则

- 飞行终点由 `codexSlotId` 的真实 DOM 边界计算，禁止写死“飞到左下角”。
- 傩谱页面在飞行开始时就已挂载于底层；飞行动画使用悬浮 `maskFlyer` 覆盖层，从坛心矩形移动到目标卡的 `getBoundingClientRect()`。
- 卡面亮起发生在面具抵达之后，随后可点击打开详情。这个顺序让“收录”有因果感。
- 动画只执行一次；`prefers-reduced-motion` 时跳过飞行并直接点亮、聚焦卡槽。

### 已有素材与新增需求

已有八职司卡面及多数详情页主面具可继续使用。得面页无需再生成一个带黑底的“伪 3D”面具。新增或复核项：

| 用途 | 数量 | 要求 |
| --- | ---: | --- |
| 可玩剧情的落坛主面具 | 4 | 透明底、眼孔镂空、与详情页主面具为同一版本 |
| 八职司匹配用正面面具 | 8 | 透明底，命名与 `maskId` 一一对应 |
| 四面中心视差用侧/背参考 | 4 组 | 现有三视图优先；边缘无白底、无裁切残留 |
| 第一幕环境图 | 4 | 16:9、无文字、与对应剧情首幕一致 |
| 傩谱卡面 | 8 | 正反面名称和 `maskId` 校对，透明区域不可出现白色棋盘格或白底 |

## 6. 组件、状态与验收

### 建议状态机

```text
name → wish → invoking → orbit → selected → cover → story
story → revealLanding → revealReady → collecting → codexFocused
```

- `invoking / orbit / selected / cover` 取代现有 `matching / mask / wearing` 的四面纸片逻辑；
- `revealLanding / revealReady / collecting / codexFocused` 取代现有直接缩小并跳转的收录逻辑；
- 每一步都携带相同的 `maskId`；只有 `mask.storyId` 存在时才允许由 `selected` 进入 `cover`。

### 代码改动边界（进入实现时）

| 位置 | 计划改动 |
| --- | --- |
| `src/domain/get-face/data.ts` | 把八职司、剧情、傩谱槽位收敛为以 `maskId` 为主键的关联；补 `storyId` 与 `codexSlotId` |
| `src/features/get-face/get-face-ritual.tsx` | 移除 `CARD_IDS`、`MASK_TITLES`、`MASK_DUTIES` 与 `slice(0, 4)`；接入八面候坛状态 |
| `src/features/get-face/get-face-ritual.css` | 删除单 PNG 的 `rotateY` 轨道；改为八槽纵深位置与盖面遮罩 |
| `src/features/get-face/get-face-result.tsx` | 用 `maskId` 读取落坛素材；收录时向真实卡槽发送飞行元素 |
| `src/features/codex/` | 每张卡暴露 `data-mask-id`，支持“接面 → 点亮 → 翻正 → 聚焦” |

### 验收清单

1. 输入困惑后可见八面，页面及辅助文字不再出现“四面”。
2. 匹配结果、入戏剧情、得面名称、图鉴卡槽四者的 `maskId` 完全一致。
3. 四条已完成剧情均能完成“入戏 → 剧情 → 得面 → 点亮正确卡面”。
4. 八面候坛没有单张平面 `rotateY` 的纸片翻转感；停定状态不持续晃动。
5. 盖面转场可从眼孔看到第一幕环境，透明处、边缘和眼孔没有黑底或白底。
6. 收录时主面具确实飞向对应卡槽；卡面在抵达后才翻正点亮。
7. 1920×1080 与窄屏下，名称、职司、按钮均单行可读；减少动态偏好可完成全部流程。

## 7. 实施顺序

1. **先定关联表**：八面 `maskId`、四条 `storyId`、八个 `codexSlotId` 做成唯一映射，并用测试锁住。
2. **完成八面候坛骨架**：先以现有透明主面具验证空间、焦点、文案和 `入戏`；暂不引入模型库。
3. **完成四条盖面转场**：统一遮罩与第一幕入口，只允许四个已有剧情目标进入。
4. **完成收录飞卡**：实现真实卡槽坐标、点亮、翻正和聚焦。
5. **替换真 3D 模型**：模型制作完成后接入 `MaskStage`，不改业务状态机。

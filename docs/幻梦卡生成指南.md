# 幻梦卡生成指南

本文面向后续负责生成或迁移 Dream Card 的 Agent。目标是让 Agent 能够新增一张符合当前项目规范的幻梦卡，并为它登记可播放的静态素材。Agent 不需要理解 React、Vite 或播放器组件实现；除非用户明确要求修改播放器，否则工作范围只应落在 `dream-card/cards/`、`dream-card/assets/` 和 `dream-card/assets/assets.manifest.json`。

## 1. 先读的权威文件

开始制卡前，先阅读以下文件，并以它们为准：

- `dream-card/create-guide/dream-card.schema.json`：Dream Card JSON 的结构约束。
- `dream-card/create-guide/dream-card.template.json`：新卡的最小模板，尤其是 `$schema`、`schemaVersion`、`meta` 和 `data.acts` 的字段形状。
- `dream-card/create-guide/assets-guide.md`：背景图、人物立绘、音频、`assetId` 和资产目录的交付规范。
- `dream-card/README.md`：只用于理解内容入口。它说明 `cards/*.json` 与 `assets/assets.manifest.json` 是唯一权威数据。
- `dream-card/cards/dream.kailu-jiangjun.du-shan-ji.json`：当前样例卡，可作为 7 幕故事、`meta.match`、`texts[]` 和资产引用的参考。
- `dream-card/assets/assets.manifest.json`：当前全局资产目录，可作为 `assetId -> file` 登记格式的参考。

不要把播放器源码当成制卡规范。`dream-card/src/`、`dream-card/player.html`、`dream-card/dist/` 属于播放器或构建产物，不是新增卡片时的默认修改对象。

## 2. 输出边界

一次标准制卡任务通常只产生三类结果：

1. 一张 Dream Card JSON：放在 `dream-card/cards/<dream-id>.json`。
2. 若干运行素材：放在 `dream-card/assets/backgrounds/`、`dream-card/assets/characters/` 或其他资产类型目录。
3. 资产目录更新：修改 `dream-card/assets/assets.manifest.json`，登记新增或替换的 `assetId`。

Dream Card JSON 只引用稳定 `assetId`，不写具体图片路径。具体文件路径只写在 `assets.manifest.json` 里。素材源文件可以放在 `dream-card/assets/source/`，但 Dream Card 和播放器运行资产不应直接引用 `source/`。

## 3. 生成一张卡的步骤

第一步，把故事拆成一个完整幻梦。当前约定是“幻梦卡 = 一个完整幻梦”，卡不是桥段类型，也不是通用剧情规则。每张卡应包含 5 至 7 个 Act；Act 是一幕，承担单一叙事功能。卡被选中后，`data` 固定播放，不再由 AI 临场改写。

第二步，先写 `meta`。`meta` 用于 AI 从卡池中选择幻梦，应写清楚标题、剧情梗概、匹配标签、适合情境、情绪、困境、关系、适合职司和文化来源。参考 `dream.kailu-jiangjun.du-shan-ji.json` 的做法：它用 `synopsis` 概括“阿渡为祖父求药而开路，并与开路将军照面”的完整主线，用 `match.tags`、`situations`、`emotions`、`dilemmas` 和 `relationships` 帮助 AI 判断何时选中这张卡。

第三步，再写 `data.acts`。每个 Act 至少要有 `id`、`title`、`backgroundAssetId`、`characters`、`texts`、`choices` 和 `notes`。`id` 使用 `act-01`、`act-02` 这种顺序编号；`choices` 在 `schemaVersion: 0.1.0` 中必须保持空数组。`notes` 可以记录场景说明、原始在场人物和迁移取舍，但播放器不应从 `notes` 猜测资产用途。

第四步，处理人物槽位。当前人物位置只支持 `left`、`center`、`right`，并且每幕最多 3 个前景人物。若原故事中同一幕有更多人物，应优先保留真正需要立绘表现的前景角色，其余人物写入 `notes` 或作为背景远景处理。样例卡第七幕原始在场包括阿渡、村中老者、祖父、众村民和戴面神秘人，但 JSON 中只摆放 3 个前景角色，祖父和众村民通过文本与备注保留。

第五步，处理文本。`texts[]` 中每个元素使用 `act-xx-text-yy` 编号；旁白可用 `speakerId: "narrator"`，动作可用 `speakerId: "stage"`，对白使用对应角色的 `instanceId` 或稳定说话人 id。建议在 `extensions.sourceType` 中标出 `narration`、`dialogue`、`action` 或 `final-narration`，并用 `speakerName` 保留中文说话人显示名。显示方式优先使用 `{"mode": "typewriter", "advance": "manual"}`，除非有明确的自动播放设计。

## 4. 资产生成与登记

先从卡片中收集全部 `backgroundAssetId` 和 `characters[].assetId`，再检查 `dream-card/assets/assets.manifest.json`。如果 `assetId` 不存在，或状态仍是 `placeholder`，就需要补素材并更新 manifest。不要为了替换素材去改播放器 HTML 或 React 代码。

背景图遵循 `assets-guide.md`：运行格式为 WebP，标准尺寸为 `1920 × 1080`，不带透明通道，不包含标题、对白、UI、水印、乱码或现代穿帮元素。背景应为人物槽位和下方对白区留出空间。文件建议放在 `dream-card/assets/backgrounds/<scene-name>.webp`。

人物立绘遵循 `assets-guide.md`：运行格式为 PNG，标准尺寸为 `1024 × 1536`，必须有透明 Alpha 通道，不包含场景背景、文字、水印或对白框。文件建议放在 `dream-card/assets/characters/<character-name>.png`。同一角色如果只是复用同一形象，保持同一个 `assetId`；如果出现明显状态变化，例如疲惫、坚定、受伤，应新增 `character.<name>.<state>` 这样的独立 `assetId`。

manifest 中每个资产至少登记这些字段：`assetId`、`type`、`file`、`mimeType`、`width`、`height`、`bytes`、`colorSpace`、`hasAlpha`、`mirrorAllowed`、`status`、`source`。字段形状以 `assets-guide.md` 第 10 节和现有 `assets.manifest.json` 为准。AI 生成素材应在 `source.reference` 或后续溯源字段中说明生成来源、风格参考和授权状态。

## 5. 使用样例卡作为参考

新增卡时，可以参考 `dream.kailu-jiangjun.du-shan-ji.json` 的几个做法：

- `meta.id` 使用稳定英文 id：`dream.kailu-jiangjun.du-shan-ji`。
- `meta.synopsis` 写完整梦境主线，而不是只写一句氛围描述。
- `officeCandidates` 记录职司匹配，例如 `office.kailu-jiangjun` 与“开路”的叙事功能。
- 每幕 `backgroundAssetId` 对应一个独立场景，例如 `background.foggy-broken-road`。
- 角色 `assetId` 可以跨幕复用，例如 `character.adu` 和 `character.masked-kailu-jiangjun`。
- 画外说话人可以保留在文本中，但不要强行突破每幕 3 个前景人物的限制。

样例卡不是新规则来源。如果样例卡和 `dream-card.schema.json` 或 `assets-guide.md` 冲突，以 schema 和 guide 为准，并在交付说明中指出样例可能需要回迁。

## 6. 不要做的事

不要修改 `dream-card/player.html`、`dream-card/src/` 或 `dream-card/dist/` 来适配单张卡。新增卡和素材时，播放器应该通过卡 JSON 与全局资产目录获得内容。

不要把图片路径写进 Dream Card JSON。JSON 只写 `assetId`，路径只进 manifest。

不要让一张卡拥有私有素材目录。素材库是全局复用的，同一个“年轻女性”“山村祠堂”“雾中山路”等素材未来可以被多张卡复用。

不要在 `schemaVersion: 0.1.0` 中填选择项。`choices` 目前只是保留字段，必须为空数组。

不要把素材缺失静默替换成“看起来差不多”的别的素材。若缺失，新增正确素材并登记；如果暂时不能生成，明确保留 `placeholder` 状态。

## 7. 交付说明

完成后，交付说明应简洁列出：

- 新增或修改的 Dream Card JSON 路径。
- 新增或替换的 `assetId` 列表。
- 更新的 manifest 路径。
- 仍为 `placeholder` 或需要人工视觉验收的资产。
- 任何为了适配规范做出的迁移取舍，例如“原始故事一幕有 5 个在场人物，当前只登记 3 个前景人物，其余保留为画外或背景远景”。

除非用户明确要求运行播放器，否则制卡任务不需要启动本地开发服务，也不需要解释 React 组件实现。

# 《大傩幻梦》资产制作与交付规范

版本：`0.1.0`  
适用范围：Dream Card 共用资产库、幻梦播放器、生图与音频制作  
状态：当前项目约束；后续如播放器画布或资产目录发生变化，应同步修订本文

## 1. 目的

Dream Card 只通过稳定的 `assetId` 引用资产，不拥有具体素材文件。不同幻梦卡可以复用同一背景、人物、音效或音乐，播放器通过全局资产目录把 `assetId` 解析为实际文件。

本文规定运行资产的格式、尺寸、构图、透明通道、文件体积、音频编码和交付检查。其目标是让不同人员、不同时间生成或绘制的素材能够直接进入同一播放器，而不需要为单张图片编写特殊布局代码。

## 2. 权威边界

- Dream Card JSON：只描述剧情、Act、文本以及所引用的 `assetId`。
- 全局资产目录：记录 `assetId`、文件位置、类型、尺寸、来源及状态。
- 本文：规定资产如何制作与验收。
- 播放器：按照资产目录加载素材，不从文件名、Dream Card 的 `notes` 或图片内容猜测资产用途。

PSD、Procreate、Clip Studio、未压缩 WAV 等创作源文件不属于播放器运行资产，不能直接被 Dream Card 引用。运行资产必须导出为本文允许的 Web 格式。

## 3. 通用画布

### 3.1 当前标准

- 舞台比例：`16:9`。
- 基准画布：`1920 × 1080 px`。
- 色彩空间：`sRGB`。
- 播放器应等比缩放完整舞台，不应为了填满竖屏而裁掉左右剧情内容。
- 当前只制作横屏资产；如未来确定以手机竖屏为主要场景，再增加独立的 `portrait` 资产变体。

### 3.2 通用禁止项

运行资产中不得包含：

- 水印、模型签名、平台标志或生成器文字。
- Dream Card 标题、对白、旁白或播放器按钮。
- 无法解释的乱码、伪文字、错误汉字或现代品牌标识。
- 与设定不符的现代器物、现代建筑、现代服装和其他时代穿帮。
- 未经确认的宗教符号拼贴，或把其他地区的傩面直接标注为贵州傩面。

## 4. 资产类型总表

| 资产角色 | 运行格式 | 基准规格 | 建议体积 | 硬上限 |
| --- | --- | --- | ---: | ---: |
| 背景图 `background` | WebP | 1920 × 1080，16:9 | ≤ 700 KB | 1.2 MB |
| 人物立绘 `character` | PNG | 1024 × 1536，2:3 | ≤ 1 MB | 2 MB |
| 前景/特效 `effect` | PNG | 按用途声明 | ≤ 500 KB | 1 MB |
| 背景音乐 `bgm` | MP3 | 48 kHz，立体声，128–192 kbps | ≤ 5 MB | 8 MB |
| 环境音 `ambience` | MP3 | 48 kHz，立体声，96–160 kbps | ≤ 3 MB | 5 MB |
| 短音效 `sfx` | MP3 | 48 kHz，单声道优先，96–160 kbps | ≤ 500 KB | 1 MB |
| 人声/旁白 `voice` | MP3 | 48 kHz，单声道，96–128 kbps | 按时长控制 | 5 MB |

人声/旁白尚未进入 Dream Card `0.1.0` 的必做范围，表中规格仅作为后续兼容预留。当前生图工作优先完成背景图和人物立绘。

## 5. 背景图规范

### 5.1 文件要求

- 运行格式必须为 `.webp`。
- 尺寸必须为 `1920 × 1080 px`。
- 使用 sRGB，不携带透明通道。
- 不得拉伸非 16:9 原图凑尺寸；应重新构图或合理裁切。
- 背景不得烘焙需要由人物槽位单独呈现的主角立绘。

### 5.2 构图安全区

- 左右各约 12% 为响应式边缘区，不放置不可裁切的关键信息。
- 下方约 28% 为对白安全区，不放置必须被看清的脸、文字或关键道具。
- 核心场景信息优先放在画面中间 76% 范围内。
- 背景可以包含远景村民、建筑、山体、树木和不可独立摆位的环境人物。
- 背景中的光源方向应明确，以便人物立绘能够选择相容的受光方向。

### 5.3 生图要求

每张背景的生成说明至少应明确：

1. 时间与地域背景。
2. 具体地点和天气。
3. 镜头景别、视角和主体位置。
4. 光源方向、色温和整体色调。
5. 必须出现的剧情物件。
6. 必须留空的人物区域和对白安全区。
7. 禁止出现的现代元素、文字、水印和主角人物。

背景生图提示记录模板：

```text
assetId：background.example
用途：第几张幻梦卡、第几个 Act，或共用场景
地点/时代：
画面主体：
镜头与构图：16:9，1920×1080，核心信息位于中央安全区
光照与色调：
关键物件：
预留人物槽位：left / center / right
禁止项：人物立绘、UI、对白、文字、水印、现代穿帮元素
参考素材：
```

## 6. 人物立绘规范

### 6.1 文件要求

- 运行格式必须为 `.png`。
- 画布尺寸必须为 `1024 × 1536 px`，比例为 2:3。
- 必须使用透明背景，并保留完整 Alpha 通道。
- 不得包含场景背景、对白框、文字、水印或不属于角色的环境阴影。
- 人物主体底部与画布底边对齐，左右各保留至少 8% 透明区，头顶至少保留 5%。
- 同一角色的不同状态应保持头身比例、服饰结构和面部特征一致。

### 6.2 视觉尺度

人物立绘采用统一画布，不由播放器针对单张素材进行任意缩放修正。生成或绘制时应保持同类人物的头部大小、肩宽和半身占比处于相近区间；角色高矮可以存在差异，但不能因为裁切方式不同而产生非设定性的巨大比例差。

当前人物位置只有 `left`、`center`、`right` 三个槽位。第一版人物优先采用正面或轻微三分之四侧面的姿态，确保放入任意槽位时都不会明显背对剧情中心。

### 6.3 朝向与镜像

- 默认不得自动水平镜像人物素材。
- 傩面、服饰、武器和纹样可能具有方向性或文化含义，镜像前必须确认。
- 允许镜像的资产应在资产目录中明确记录 `mirrorAllowed: true`。
- 如左右朝向具有实质差异，应生成独立变体并分配不同 `assetId`。

### 6.4 表情与状态变体

同一角色的明显状态变化应使用独立 `assetId`，例如：

```text
character.adu.neutral
character.adu.exhausted
character.adu.determined
```

不同变体必须保持角色身份一致，不得只因为重新生图而改变年龄、脸型、发型、服装纹样或身体比例。若只是颜色校正、去除瑕疵或重新压缩，不改变素材语义，则可以保持原 `assetId` 并更新资产版本。

### 6.5 生图要求

人物生图提示记录模板：

```text
assetId：character.example
角色身份：
年龄与体态：
面部稳定特征：
服饰与关键配件：
表情/状态：
姿态与视角：正面或轻微三分之四侧面
画布：2:3，1024×1536，透明背景，底部对齐
光照方向：
禁止项：场景背景、文字、水印、额外肢体、错误手指、身份漂移
参考素材：
```

## 7. 前景与特效规范

- 前景雾、雨、火星、光束等素材使用透明 PNG。
- 特效只能增强氛围，不能承载缺失后就无法理解的核心剧情信息。
- 当前不接受 GIF、APNG、动画 WebP 或视频作为 Dream Card 运行资产。
- 简单动态效果优先由播放器使用 CSS 实现，例如雾气漂移、淡入、轻微缩放和明暗变化。
- 如未来引入序列帧或视频，应先扩展资产目录和播放器能力，不得直接把新格式塞入现有 `effect` 类型。

## 8. 音频规范

### 8.1 通用要求

- 运行音频统一使用 `.mp3`。
- 采样率统一为 `48 kHz`。
- 创作源文件建议保留无损 WAV，但 Dream Card 不得直接引用创作源文件。
- 文件开头和结尾不得存在无意的长静音、爆音或突然截断。
- 标题页加载完成后不得自动播放；必须在用户点击“进入幻梦”等明确交互后启动音频。

### 8.2 响度建议

- 背景音乐与环境音：约 `-20 LUFS`。
- 后续人声/旁白：约 `-16 LUFS`。
- 交付音频峰值不超过 `-1 dBTP`。
- 短音效不强制统一 LUFS，但不得明显压过对白和旁白。

### 8.3 循环音频

- 需要循环的素材必须在资产目录中标注 `loop: true`。
- 当前 MP3 方案不承诺采样级无缝循环；制作时应避免在循环边界出现强节拍、突然断音或明显环境变化。
- 如未来需要严格无缝循环，再评估 Opus 或多格式音频源，不在 `0.1.0` 中提前扩展。

## 9. assetId 与文件命名

### 9.1 assetId

`assetId` 表达稳定的素材身份，不表达临时文件路径。建议使用以下命名空间：

```text
background.<scene-name>[.<variant>]
character.<character-name>[.<state>]
effect.<effect-name>[.<variant>]
bgm.<music-name>[.<variant>]
ambience.<scene-name>[.<variant>]
sfx.<action-name>[.<variant>]
voice.<character-name>.<line-or-group-id>
```

示例：

```text
background.foggy-broken-road
character.adu.exhausted
effect.mountain-fog.light
ambience.mountain-night
sfx.axe-hit-stone
```

### 9.2 文件名

- 文件名使用小写英文、数字、点号和连字符，不使用空格。
- 文件名可以与 `assetId` 相同，但资产目录仍是 `assetId → file` 的唯一权威映射。
- 文件格式或物理路径变化时，不应因此修改 `assetId`。
- 素材的身份、状态或视觉语义发生变化时，应创建新的 `assetId`。

## 10. 资产目录最低字段

后续全局资产目录中的每个资产至少应记录：

```json
{
  "assetId": "character.adu",
  "type": "character",
  "file": "files/characters/adu.png",
  "mimeType": "image/png",
  "width": 1024,
  "height": 1536,
  "bytes": 842316,
  "colorSpace": "sRGB",
  "hasAlpha": true,
  "mirrorAllowed": false,
  "status": "draft",
  "source": {
    "type": "generated",
    "reference": "",
    "license": "project-owned"
  }
}
```

对 AI 生成素材，还应保留模型、提示词、负面提示词、参考图、种子（如可用）和生成时间。该记录用于复现角色风格、追踪素材来源和继续生成同一角色变体，不直接进入播放器展示。

## 11. 缺失与不合规资产

- `draft` 阶段：素材缺失时，播放器显示带 `assetId` 的占位画面并给出警告，剧情仍可继续播放。
- `review` 阶段：所有引用的 `assetId` 必须存在，允许存在体积或建议值警告。
- `ready` 阶段：所有引用资产必须存在，并满足格式、尺寸、透明通道和硬性体积限制。
- 音频加载失败不得阻断剧情；背景和人物加载失败不得导致播放器崩溃。
- 播放器不得用其他看似相近的素材静默替代缺失的 `assetId`。

## 12. 交付检查清单

### 背景图

- [ ] WebP，1920×1080，sRGB。
- [ ] 文件不超过 1.2 MB。
- [ ] 无文字、水印、UI 和主角立绘。
- [ ] 中央安全区包含核心场景信息。
- [ ] 下方对白区没有必须看清的内容。
- [ ] 光源方向和色调已记录。

### 人物立绘

- [ ] PNG，1024×1536，sRGB。
- [ ] 透明背景且 Alpha 边缘干净。
- [ ] 文件不超过 2 MB。
- [ ] 底部对齐，头顶和左右留白符合要求。
- [ ] 与同角色已有变体的身份、服饰和比例一致。
- [ ] 无文字、水印、场景背景和多余肢体。
- [ ] 是否允许镜像已经明确。

### 音频

- [ ] MP3，48 kHz。
- [ ] 声道和码率符合资产类型。
- [ ] 无爆音、意外长静音和突然截断。
- [ ] 响度与峰值符合建议。
- [ ] 是否循环已经明确。
- [ ] 音频缺失不会阻断剧情。

### 来源与复现

- [ ] 已分配稳定且语义明确的 `assetId`。
- [ ] 已记录文件路径、类型、尺寸和体积。
- [ ] 已记录素材来源与使用权状态。
- [ ] AI 生成素材已保留模型、提示词、参考图及其他可用生成参数。
